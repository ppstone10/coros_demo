# 可编辑正常健康数据 Spec

## 元数据

- Spec ID 前缀：`HLTH-EDIT`
- 状态：已实施
- 负责人：Codex / 人工评审
- 关联需求：`new.md`
- 最后更新：2026-07-30

## 目标

- 将 `Normal` 健康 Mock 场景从固定完整展示数据改为可编辑的最小源数据。
- 保留“选择场景后必须下拉刷新才更新首页”的真实 App 同步过程。
- 默认数据、进程内编辑数据和用户有效持久化数据使用同一份最小字段契约。
- 所有校验、序列生成和派生值计算位于 KMP `common`；三端只负责原生导航、表单输入与渲染。
- 支持顶部摘要与 14 类卡片逐项编辑、单项恢复默认，以及总览页整套使用默认数据。
- 体型管理卡片根据 common 输出的锻炼部位，以同画布人体蒙版高光实际肌肉区域。

## 非目标

- 不接入真实传感器、服务地址、账号、token 或用户真实健康服务。
- 不持久化尚未通过首页刷新提交的临时正常数据。
- 不允许编辑 `PartialMissing`、`AllEmpty`、`Abnormal` 或 `ReadFailure` 固定场景。
- 不把派生文案、状态、图表坐标、仪表高光、肌肉蒙版编号或统计结果作为新快照的权威源字段。
- 不改变既有“编辑卡片”页面的显示、隐藏与排序职责。

## 边界与约束

- `common` 定义源数据模型、默认 fixture、校验、派生算法、临时草稿和刷新提交。
- Android Compose、iOS SwiftUI 与 HarmonyOS ArkUI 只维护控件展示值并把原始输入提交给共享门面。
- 心率和压力编辑器中的平均值/变化模式只是快捷生成参数；保存到草稿和快照的是完整序列。
- 睡眠编辑器中的总时长是快捷划分参数；权威源字段是入睡时间和连续睡眠阶段区间。
- 睡眠阶段和锻炼部位均为动态重复项；新增、删除、重新编号和合法选项由 common 表单规则负责，平台不得复制这些规则。
- 三端编辑控件必须在已有值存在时仍显示常驻字段提示；重复项使用 common 提供的序号参数，不显示字段 ID。
- 体型管理只允许选择 common 定义的实际锻炼部位；common 负责把部位派生为稳定高光区域 ID，三端只映射并叠加同画布蒙版，不能复制部位到区域的组合规则。
- 体型人体底图和蒙版使用 `660×1260` 透明同画布资源；平台不得通过近似圆点或自行绘制不同形状代替。
- 保存提示持续 `1500ms`，采用 latest-wins：新提示立即替换旧提示并重新计时，不排队。
- 临时草稿生命周期为当前 `HealthStore` 实例；进程重建后允许丢失。
- 刷新成功后的用户有效源数据按认证 `userId` 持久化；刷新失败不得覆盖最后有效快照。

## 数据与状态

| 名称 | 类型/结构 | 来源 | 生命周期 | 约束 |
|------|-----------|------|----------|------|
| 内置正常源数据 | `EditableHealthData` | common fixture | 应用版本 | 只包含权威源字段 |
| 临时正常草稿 | `EditableHealthData?` | 编辑器 | `HealthStore` 进程内 | 不进入 JSON/Proto 快照 |
| 当前有效源数据 | `EditableHealthData?` | 最近成功刷新 | 按用户持久化 | 加载时重新派生 `HealthDashboardData` |
| 待刷新场景 | `HealthMockScenario?` | 场景选择器 | `HealthStore` 进程内 | 选择不立即改变首页 |
| 展示数据 | `HealthDashboardData` | common 派生规则 | 内存 | 不是新版快照权威字段 |

最小源字段：

- 顶部摘要：步数、卡路里、运动时长。
- 今日活动：总里程、配速。
- 本周计划：七日休息状态，或跑步类型与公里数。
- 本周负荷：七日负荷。
- 训练量评估：短期负荷、长期负荷。
- 体力恢复：体力百分比。
- 跑步能力：0–100 能力值。
- 骑行能力：0–100 FTP 能力值。
- 心率：288 个五分钟采样值。
- 压力：48 个半小时采样值。
- 睡眠：入睡时间与数量可变的连续睡眠阶段区间。
- HRV：平均 HRV。
- 静息心率：当前值、测量时间、近 30 天平均值。
- 健康快测：心率、HRV、压力、呼吸率、血氧和测量时间。
- 体型管理：当前体重、数量可变且来自共享选项集的锻炼肌肉部位，并继续保留既有体重历史契约。

## 行为规范

### `HLTH-EDIT-001`：最小源数据统一默认与持久化

- Given：内置正常 fixture 或一次刷新后的用户有效数据
- When：编码持久化或恢复
- Then：只保存最小源字段；今日活动类型、训练负荷、负荷比、恢复时长、能力预测、状态文案和图表数据由 common 重新计算
- 异常/边界：旧版完整 `dashboardData` 快照迁移为最小源数据后继续可用

### `HLTH-EDIT-002`：临时草稿与刷新提交分离

- Given：用户在正常数据编辑器保存一项或多项修改
- When：尚未下拉刷新
- Then：首页和持久化快照不变，修改只存在当前 `HealthStore` 内存
- When：选择 `Normal` 并刷新成功
- Then：使用临时草稿派生首页并持久化其最小源数据
- 异常/边界：进程重建前未刷新的草稿允许丢失；刷新失败保留草稿与最后有效快照

### `HLTH-EDIT-003`：单卡与整套默认恢复

- Given：存在正常数据临时草稿
- When：在卡片编辑页恢复默认并保存
- Then：只替换该模块草稿为 common 默认源字段
- When：在正常数据总览点击“使用默认数据”
- Then：整套临时草稿替换为 common 默认源数据
- 异常/边界：两种恢复都不直接改变首页，仍需刷新

### `HLTH-EDIT-004`：派生规则只位于 common

- Given：三端提交相同源数据
- When：计算今日活动、计划、负荷、评估、恢复、能力、HRV、静息心率、快测或体型数据
- Then：三端得到同一 `HealthDashboardData` 和 UI model
- 异常/边界：非法数值由 common 拒绝，不允许平台自行夹紧后形成不同业务结果

### `HLTH-EDIT-005`：完整序列由共享快捷生成器产生

- Given：心率平均值与正常/异常高/异常低模式，或压力平均值与正常/高压模式
- When：用户请求生成
- Then：common 分别生成恰好 288 个五分钟心率样本或 48 个半小时压力样本，且数值范围合法、结果确定
- And：生成参数不持久化，保存的是完整序列
- 异常/边界：生成后可再次编辑参数覆盖序列

### `HLTH-EDIT-006`：编辑导航与场景边界

- Given：用户打开场景选择器
- When：进入 `Normal`
- Then：可 Push 正常数据编辑总览，再 Push 顶部摘要或任一卡片编辑页
- When：选择其他场景
- Then：保持既有固定场景选择行为，不展示数据编辑入口
- And：数据编辑路由与既有卡片排序编辑路由相互独立

### `HLTH-EDIT-007`：短时保存反馈

- Given：用户连续保存不同卡片
- When：产生新的保存成功事件
- Then：三端立即以新卡片提示替换旧提示，并在 1500ms 后消失
- 异常/边界：旧提示的计时器不得清除后发提示

### `HLTH-EDIT-008`：睡眠阶段保持连续

- Given：用户输入入睡时间和总睡眠时长，并依次划分阶段
- When：保存睡眠草稿
- Then：阶段按开始分钟连续排列、持续时间均为正数，结束时间由总分钟数计算
- 异常/边界：空阶段、重叠、间隙、越界或非正时长由 common 拒绝

### `HLTH-EDIT-009`：共享健康语义键必须接入平台解析白名单

- Given：common 的正常数据派生规则或编辑表单输出一个 `health_edit_*` / 新增 `health_visual_*` 语义键
- When：Android 或 HarmonyOS 渲染该键
- Then：平台显式本地化解析入口必须映射到同名原生资源，不能回退为“数据不可用”、空白或资源键名
- 异常/边界：新增共享健康键时，资源目录和显式解析白名单必须由同一门禁共同检查

### `HLTH-EDIT-010`：三端编辑控件和常驻提示一致可读

- Given：任一卡片编辑页已加载已有值
- When：Android、iOS 或 HarmonyOS 渲染表单
- Then：顶部保存按钮完整可见且可点击；每个输入/选择控件上方或同一容器内持续显示本地化字段提示
- And：Android 输入文字、光标、标签和边框与深色背景保持足够对比；三端不展示 `stage0Type` 等技术字段 ID
- 异常/边界：标题较长或字段已有值时，不得挤压保存按钮或令提示消失

### `HLTH-EDIT-011`：睡眠阶段由共享表单动态增删

- Given：睡眠编辑器存在至少一个阶段
- When：用户新增或删除任一阶段
- Then：common 根据当前未保存输入返回重新编号后的表单；每个阶段仍可独立选择类型和编辑正时长
- And：保存时 common 按表单中的实际阶段数量重建从 0 开始连续的阶段区间
- 异常/边界：最后一个阶段不可删除；总时长超过 1440 分钟、空阶段或非正时长时保存失败

### `HLTH-EDIT-012`：锻炼部位使用共享可选集合并支持动态增删

- Given：体型管理编辑器
- When：用户新增锻炼部位、切换部位或删除已有部位
- Then：common 返回数量可变的 Choice 字段，选项限定为胸部、肩部、背部、肱二头肌、肱三头肌、腹部、臀部、股四头肌、腘绳肌和小腿
- And：保存时去重并拒绝未知部位；允许删除到零个锻炼部位
- 异常/边界：新增项优先选择尚未使用的部位；所有部位已使用时不再新增

### `HLTH-EDIT-013`：体型卡片图示反映有效锻炼部位

- Given：正常数据草稿已通过首页刷新成为当前有效数据
- When：三端渲染体型管理卡片
- Then：右侧人体前后视图区域使用 common 输出的部位 ID 和本地化名称标记当前锻炼部位
- 异常/边界：无部位时显示无本周锻炼部位的共享提示；不得继续固定声称胸部或股四头肌已训练

### `HLTH-EDIT-014`：HarmonyOS HRV 范围信息完整显示

- Given：HRV 评估具有当前值和正常范围
- When：HarmonyOS 渲染右侧范围横条
- Then：当前值三角标记、横条以及下方正常范围图例均在卡片范围内完整显示
- 异常/边界：极小或极大值时标记夹紧在横条两端且不被容器裁剪

### `HLTH-EDIT-015`：三端枚举选择器与重复项布局统一

- Given：任一卡片编辑页包含睡眠阶段、锻炼部位或其他 `Choice` 字段
- When：Android、iOS 或 HarmonyOS 渲染该字段
- Then：字段提示与当前选择值位于同一行，当前值使用健康强调色并显示下拉指示，不通过连续点击直接轮换选项
- When：用户点击字段
- Then：三端均显示居中的深色圆角选择面板；面板包含字段标题、纵向选项、当前项勾选和底部取消操作，点击选项后更新本地表单值并关闭
- And：动态重复项的添加按钮在三端统一使用 `AddAction` 绿色；睡眠阶段、锻炼部位及后续共享重复项遵循同一组件规则
- 异常/边界：点击遮罩或取消只关闭面板且不修改值；选项较多时面板内容可滚动，不能超出安全区

### `HLTH-EDIT-016`：选择器状态图标复用三端共享资源

- Given：三端 Choice 字段入口和选择面板当前项需要显示下拉指示与勾选状态
- When：页面渲染两类图标
- Then：三端均复用已登记共享资源 `right_more` 与 `ic_profile_check`，不得继续使用字体字符 `⌄`/`✓` 或 iOS SF Symbol
- And：`right_more` 统一旋转 90°形成向下指示，`ic_profile_check` 统一使用 Template/Tint 着为健康强调红色；两类图标保持相同语义尺寸与无障碍装饰属性
- 异常/边界：图标资源加载失败不得改变字段值、弹层选择或保存业务；不得为本规则复制一套可见像素相同但语义不同的新资源

### `HLTH-EDIT-017`：体型管理按部位高光实际肌肉区域

- Given：正常数据草稿中的锻炼部位已通过首页刷新成为当前有效数据
- When：common 派生体型管理卡片视觉数据
- Then：输出稳定 `highlightedBodyRegions`；胸、肩、肱二头肌、肱三头肌、腹部、臀部、股四头肌、腘绳肌和小腿映射到各自前/后视图区域，`back` 同时映射斜方肌、背阔肌和竖脊肌区域
- And：三端在同尺寸中性正反面人体底图上叠加对应透明蒙版，并统一使用健康强调红色；不再显示近似定位圆点
- And：人体图下方只显示共享文案“本周锻炼部位”/“Muscle groups trained this week”，具体部位不再以名称列表重复展示
- 异常/边界：零个部位时只显示中性人体底图和底部说明；重复部位或重叠区域由 common 去重，平台资源映射失败不得影响其他区域

### `HLTH-EDIT-018`：刷新时锻炼部位草稿优先于旧体型快照

- Given：用户已经通过体重入口形成多条持久化体重历史，并在正常数据编辑器把锻炼部位改为另一组
- When：保存体型管理草稿但尚未刷新
- Then：首页人体图仍显示旧有效部位
- When：选择 `Normal` 并完成首页刷新
- Then：只从旧有效数据保留用户体重及完整体重历史；锻炼部位必须采用本次临时草稿，并由 common 重新派生 `highlightedBodyRegions`
- And：刷新后的最小源快照保存新的 `trainedMuscleGroups`，应用重建后继续显示相同高光区域
- 异常/边界：不得为保留体重历史而用整个旧 `BodyManagementInput` 覆盖草稿；刷新失败时仍保留草稿和旧有效高光

### `HLTH-EDIT-019`：HarmonyOS 模块编辑页保存按钮可点击并使用布尔结果

- Given：HarmonyOS 用户进入任一正常数据模块编辑页且表单已经加载
- When：用户点击右上角“保存”
- Then：顶栏使用具有完整点击热区的原生 `Button` 触发一次保存；KNOI bridge 直接以 `boolean` 返回 common 保存结果，不得把布尔值转换成字符串后再比较 `'true'`
- And：保存成功显示既有 1500ms 提示并返回编辑总览；保存失败停留当前页并显示校验提示
- And：保存执行期间按钮临时不可重复点击，完成或异常后恢复；表单值仍通过既有 percent-encoded `valuesSpec` 提交给 common
- 异常/边界：页面参数或表单校验失败不得返回上一页，也不得把失败当成功；按钮文案继续使用 `common_save` 原生资源

### `HLTH-EDIT-020`：体型管理编辑器只编辑锻炼部位

- Given：三端打开正常数据中的体型管理编辑页
- When：common 生成表单、动态增删部位或保存表单
- Then：表单只包含数量可变的锻炼部位 Choice 字段，不包含 `weightKg` 输入框
- And：保存只更新 `trainedMuscleGroups`，原体重与完整体重历史保持不变
- 异常/边界：体重继续只能通过健康首页体型管理卡片的体重入口编辑

### `HLTH-EDIT-021`：iOS 编辑器以当前表单值初始化输入

- Given：iOS 当前存在 normal 内存草稿或持久化正常数据
- When：用户进入任一正常数据模块编辑页
- Then：所有输入与选择控件从 common 返回的当前表单值初始化，不显示全空临时字典
- And：视图首次渲染或 SwiftUI 状态重建期间，本地输入字典缺键时回退到字段自身 `value`
- 异常/边界：用户已经输入的本地值优先于字段初始值；恢复默认和动态增删仍整体替换为 common 返回的新表单

### `HLTH-EDIT-022`：编辑器投影当前场景的同构健康数据

- 正常、部分缺失、全空、异常和数据损坏五个场景共享同一 `HealthDashboardData` 类型；是否可编辑不得以场景枚举决定数据类型。
- 打开编辑器时，common 按“当前进程内场景数据 → 当前用户持久化快照 → 默认正常数据”的顺序解析来源；异常场景已有字段必须原值回填，不得因 `sourceScenario != Normal` 整体置零。
- 展示模型中的派生字段反投影为最小可编辑字段；只有缺失模块映射为该模块的 0、空时间或无选择占位。
- 保存一个模块只校验并替换该模块，不得因其他模块处于缺失占位而拒绝保存；刷新提交时未编辑的缺失模块继续保持 `null`。

### `HLTH-EDIT-023`：全空与数据损坏来源语义不可合并

- 全空场景表示读取成功且所有健康模块为 `null`，编辑值映射为 0/无数据，来源状态为 `Empty`。
- 数据损坏场景表示读取失败、没有可信健康数据，编辑值同样映射为 0/无数据，但来源状态为 `Corrupted`。
- 部分缺失场景来源状态为 `Partial`；完整正常或异常数据为 `Available`。
- 三端编辑总览和模块页必须展示来源提示，不能因为可见输入值相同而把 `Empty` 与 `Corrupted` 当成同一状态。

### `HLTH-EDIT-024`：保存失败返回具体字段和审核原因

- common 表单审核返回结构化结果：是否成功、字段 ID、字段本地化标签、原因类型以及范围/数量参数。
- 至少区分：必填为空、不是数字、超出允许范围、选项非法、数量不符、睡眠阶段不连续。
- 三端使用本地资源组合“字段 + 原因”，不得只显示通用“数据不合法”。
- 审核只针对当前编辑模块；异常场景的合法高/低值只要位于字段契约范围内就应通过，业务上的“异常”不是数据格式非法。

### `HLTH-EDIT-025`：HarmonyOS 输入控件在逐字符更新时保持稳定身份

- HarmonyOS 编辑模块使用字段稳定 ID 作为 `ForEach` key，输入值不得参与组件身份。
- `TextInput.onChange` 只更新对应字段的值，不得因为每次字符变化销毁并重建输入控件。
- 连续输入数字、字母或删除字符时，焦点必须留在当前输入框；只有用户主动点击、键盘 Next 或页面操作才允许切换焦点。
- 睡眠等重复字段同样使用稳定字段 ID；动态添加、删除行时由字段 ID/行索引变化驱动必要重建。
