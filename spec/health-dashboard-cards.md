# S04-A 首页健康总览卡片

## 基本信息

- 所属实习生：S04
- 候选方案：A
- 项目方向：健康总览 / 数据聚合 / 卡片排序
- 推荐架构：MVVM 或 MVI

## 配套公共文档

请同时阅读 [公共培训要求](common-training-requirements.md)。公共文档包含项目来源、内测版本、Figma、KMP + Native UI 技术栈、安全边界、Protocol Buffers mock 数据结构、注册登录门禁、统一交付物、Codex 记录、评分和里程碑要求。

## 适用画像

适合产品感较好、能兼顾数据逻辑和展示体验的实习生。

## 项目目标

实现一个脱敏健康首页，聚合睡眠、今日运动、训练负荷、恢复状态等卡片，并根据数据状态输出展示优先级。

## 实现范围

- mock 数据源：daily summary、sleep summary、training load、recovery。
- 卡片类型：睡眠、今日运动、训练负荷、恢复状态；每类业务卡通过自身的 Empty 状态、引导摘要和操作入口承担空态引导，不增加独立的 `EmptyGuide` 卡片类型。
- 排序策略：有风险提醒优先、今日数据优先、无数据降级。
- UI model：每张卡片输出标题、摘要、状态、操作入口。
- mock 场景：正常、部分缺失、全空、异常值。

## 稳定规范

### HLTH-EMPTY-001：卡片内空态引导

- 全空场景继续保留用户当前启用的业务卡片，每张卡片降级为 `Empty` 状态，不替换为单独的全局空态卡。
- 睡眠、今日运动、训练负荷、恢复状态四类核心卡片的 Empty 摘要必须说明产生数据的方式；需要进入详情或执行操作时保留有效 action。
- 三端使用相同本地化语义键，最终文案由各端原生资源解析。

### HLTH-CONTRACT-001：类型化 Mock 场景与错误契约

- `health_dashboard_mock.proto` 必须定义健康场景 enum、健康错误 enum 和错误 message。
- 健康场景至少覆盖正常、部分缺失、全空、异常值和读取失败。
- 健康错误至少覆盖未登录、空数据、损坏数据、读取失败和保存失败。
- KMP domain 场景与错误必须和 Proto 契约双向映射，未知值采用安全默认值。

### HLTH-CONTRACT-002：旧快照兼容迁移

- 新健康快照以 Proto enum 名称保存场景。
- 已保存的 `Normal`、`PartialMissing`、`AllEmpty`、`Abnormal`、`ReadFailure` 字符串快照仍必须可读取。
- 旧快照成功加载并再次保存后升级到当前 schema，不丢失卡片配置或完整健康数据。

### HLTH-SCENARIO-001：共享场景目录

- common 输出稳定的场景 code 与显示文案 key 目录。
- Android、iOS、HarmonyOS 的场景选择器消费该目录，不各自维护业务场景字符串数组。
- Native UI 只负责本地化展示、选中状态和点击交互。

## 完成档位

- 基础要求：通过注册登录硬门禁，健康总览卡片可运行，业务 mock 数据源能验证未登录拦截。
- 标准要求：完成卡片聚合、排序、空态、错误态和本项目测试要求。
- 挑战要求：支持卡片配置、局部刷新、趋势摘要和可复用 dashboard state。

## 验收标准

- 正常、空数据、部分数据、异常数据均可展示。
- 卡片展示优先级可解释。
- 业务规则层输出稳定 UI model。
- UI 不直接拼多源数据聚合规则。
- 全空时各业务卡输出可操作的 Empty 引导，不要求独立空态卡。
- 新旧健康场景快照均可恢复，三端场景目录来自 common。

## 测试要求

- 至少 12 条单元测试。
- 必须覆盖全量数据、睡眠缺失、今日运动缺失、恢复状态异常、卡片排序。
- 必须覆盖冷静态场景/错误 Proto 映射、旧场景字符串迁移和核心 Empty 引导契约。

## 观察点

- 是否能主动考虑空态和用户理解成本。
- 是否能把"展示优先级"写成可测规则。
- 是否能兼顾产品体验和工程分层。
